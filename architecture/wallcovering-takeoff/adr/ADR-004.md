# ADR-004: All reading enters through a pluggable ExtractionPort; manual entry is the v1 adapter

- **Status:** ACCEPTED
- **Feature:** wallcovering-takeoff
- **Requirements:** FR-3, FR-4, NFR-3, NFR-4

## Context

The source recommends shipping manual entry first for trustworthiness and layering vision pre-fill later, without letting an unconfirmed machine-read number reach an order. Wiring a reader directly into the domain would make that later addition a rewrite and would place a non-deterministic component on the compute path.

## Decision

Define ExtractionPort as the single boundary for tags, dimensions and schedule fields. Every adapter returns Proposal objects carrying source, confidence and confirmed=False. ManualEntryAdapter is the only v1 implementation; VisionPrefillAdapter is deferred to v1.1, is opt-in, and neither adapter may import or invoke TakeoffEngine.

## Consequences

Positive: v1 is fully offline and deterministic, adding vision or an OCR adapter for the schedule table changes no domain, math, review or export code, and the guarantee that a reader cannot compute is structural. Negative: an extra indirection even for manual entry, and every read value carries provenance metadata the manual path barely needs.
