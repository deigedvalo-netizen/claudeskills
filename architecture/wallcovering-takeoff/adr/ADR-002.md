# ADR-002: Set-read and compute are separate modules with a one-way dependency

- **Status:** ACCEPTED
- **Feature:** wallcovering-takeoff
- **Requirements:** FR-2, FR-5, FR-8, NFR-1

## Context

The requirement source draws a hard line: schedule-sourced values are read verbatim and never derived, while quantities are computed. Enforced only by convention, this line erodes the moment a convenience helper back-fills a missing roll width or normalises a repeat.

## Decision

Place set-read state in SetReadRegistry, which exposes storage and retrieval and no arithmetic at all, and place all arithmetic in TakeoffEngine, GeometryService and AggregationService, which consume WCDefinition as immutable constants. The dependency runs one way, compute imports set-read and never the reverse, and any absent schedule field is an explicit UNKNOWN sentinel rather than a default or an imputed value.

## Consequences

Positive: the boundary becomes mechanically checkable, an UNKNOWN cannot be arithmetically consumed, and provenance stays intact for NFR-1. Negative: more ceremony around every schedule field, and callers must handle UNKNOWN explicitly at each use site rather than relying on a default.
